# 人数カウンター & グループ分け

イベント受付で来場者を男女別にカウントしながら、**その場で男女バランスを保ったグループ分け**を行うツール。別の端末を「モニター画面」にすると、受付の操作がリアルタイムで来場者側のディスプレイに映る。

**Firebase Firestore / Vanilla JavaScript (ES Modules) / Vercel / ビルド不要の単一 HTML**

---

## 解決した課題

交流イベントの受付で、来場者を数えながらグループ分けをする必要があった。紙で運用すると

- 受付が混むと数え間違える
- グループの**男女比が偏る**
- 来場者が「自分がどのグループか」を受付で聞かないと分からない

このツールは、受付担当が `+1〜+5` のボタンを押すだけで、カウントとグループ割り当てが同時に進む。割り当て先は画面にトーストで出るため、その場で来場者に伝えられる。モニター画面を併用すれば、来場者が自分で確認できる。

## 技術的な工夫

### グループ分けは「性別ごとに別々に均す」

全体の人数だけを見て均すと男女比が偏るため、**性別ごとに独立して最小のグループへ入れる**方式にした。

- **追加時** — その性別の人数が最も少ないグループを探し、そこへ追加する
- **削除時** — その性別の人数が最も多いグループから、末尾の1人を外す

追加と削除で逆向きの基準（最小／最大）を使うことで、増減を繰り返しても各グループの男女比が均衡に戻る。

全体を組み直すときは **Fisher-Yates シャッフル**でメンバー順を混ぜてから、同じルールで再配分する。

### 複数端末のリアルタイム同期

Firestore の単一ドキュメント（`appData/counter1`）を共有状態として扱い、受付端末が `setDoc` で書き込み、受付端末とモニター端末の両方が `onSnapshot` で購読している。

- 受付端末も自分の書き込みを購読しているため、**受付を2台にしても両方に反映される**
- モニター端末（`monitor.html`）は購読のみで、書き込み処理を一切持たない。来場者側の画面から状態を壊せない

状態をサーバ側の1ドキュメントに集約したので、同期のための自前の通信コードは書いていない。

### 運用から生まれた仕様変更

コミット履歴に残っている2つの変更は、どちらも実際に使ってみて出た要望から入れたもの。

- **グループ名を数字から「あ・い・う…」に変更した。** 「3番グループ」より「うグループ」のほうが口頭で伝えやすく、聞き間違いが減る
- **一度に追加する人数を1〜5名から選べるようにした。** 家族や友人同士でまとめて来る来場者を**同じグループに入れる**ため。選んだ人数分を同一グループへ連続で追加する（減らすときは常に1人ずつ、という元の挙動は維持した）

### その他

- 男女比を横並びのプログレスバーで表示し、偏りを視覚的に把握できる
- グループ名は画面上で直接編集できる
- Vercel へのデプロイ時に、`vercel.json` でセキュリティヘッダ（`X-Content-Type-Options: nosniff` / `X-Frame-Options: DENY` / `X-XSS-Protection`）を付けている

## 構成

```
index.html    # 受付用（カウント・グループ分け・編集）
monitor.html  # 来場者向けモニター表示（読み取り専用）
vercel.json   # 静的配信とセキュリティヘッダ
```

どちらも単一 HTML でビルド不要。Firebase SDK は CDN から ES Modules として読み込んでいる。

## 使い方

1. 受付端末で `index.html` を開き、グループ数を入力する
2. `+1`〜`+5` / `-1` で来場者をカウントする。割り当て先がトーストで表示される
3. 来場者側のディスプレイでは `monitor.html` を開く
4. 「リセット」で次のイベント用に初期化する

## 制約

- Firebase の設定値が HTML に直接書かれており、認証を持たない。URL を知っていれば誰でも書き込めるため、**イベント当日のみ使う前提**の割り切り
- 共有ドキュメントが1つ固定（`appData/counter1`）なので、同時に複数のイベントで使えない
- 個人を識別せず、性別の人数だけを扱う（氏名などは保持しない）
